# 相关性标注指南（Day 8）

> 人工标注与 Claude 标注**共用这一份文件**：`tools/eval_build/label.py` 把它原样作为 system prompt。
> 改了指南就要重标——kappa 衡量的是「这份指南能不能让两个标注者得出同样的判断」，
> 两边看到的不是同一份指南，kappa 就没有意义。

## 你在做什么

给定一条**搜索 query** 和一条**候选帖子**，判断这条帖子对发出这条 query 的用户有多大价值，打 0 / 1 / 2 分。

- 只看 query 和帖子正文本身。不要猜这条帖子是哪个检索系统返回的、排第几名。
- **不看字面是否重合**。一条帖子和 query 一个字都不重合，也可以是 2 分；
  反过来，共享关键词但讲的是另一件事，就是 0 分。
- 帖子写得好不好、建议对不对，不影响分数。只判断**相关性**。
- 帖子来自哪个来源（看上去像合成的、像 2012 年的旧微博）都照常判定，不因来源降分。

## 先判断 query 属于哪一类

每条 query 带有类型标签，按标签选用下面的标准：

| 类型 | 用户想要什么 |
|---|---|
| `keyword` / `synonym` / `mixed` | **求答案**：想知道某个具体问题怎么办、值不值、是什么 |
| `resonance` | **求同类**：想看到和自己处境相同的人怎么说，不是要解决方案 |
| `no_answer` | 站内大概率没有相关讨论。照常按「求答案」标准判定，多数应为 0 |

## 求答案类（keyword / synonym / mixed / no_answer）

| 分 | 定义 | 例（query：「怎么防止超卖」） |
|---|---|---|
| **2** | 帖子**直接针对 query 的问题**给出了信息：做法、经验、数字、结论、踩过的坑 | 讲库存扣减用 Redis 预减 + Lua 原子操作的帖子 |
| **1** | 同一话题、对用户有参考价值，但**没有直接回答**：只讲了相邻的子问题、只描述现象没给信息、信息过于笼统 | 讲分布式锁选型但没提库存的帖子 |
| **0** | 不同话题；或只是共享关键词；或纯情绪、没有任何信息 | 讲「双十一抢购没抢到」的吐槽 |

判别要点：
- **提问帖**（「有没有人知道……？」）本身不含答案。与 query 问的是同一个问题时给 **1**，不给 2——它说明有人关心，但用户读完拿不到答案。
- 帖子讲的是 query 问题的**一个具体情形**（query 问租房押金，帖子讲退租时押金被扣并给出取证办法）→ **2**。
- 只在一句话里顺带提到 query 的话题，主体在讲别的 → **1** 或 **0**，看那一句有没有信息量。

## 求同类（resonance）

共鸣类的「相关」是主观的，这是整套评测最容易被质疑的地方。判断时拆成三个维度：

| 维度 | 问自己 |
|---|---|
| **压力源** | 让人难受的是不是同一件事？（工作、关系、家庭、身体、学业、居住、失去……要具体到「上班本身」vs「找不到工作」这一层） |
| **情绪状态** | 是不是同一种感受？（疲惫麻木、焦虑心慌、孤独、委屈、后悔、思念……） |
| **处境** | 人生阶段与场景是否相近？（学生 / 刚工作 / 中年；独居 / 和家人住） |

| 分 | 定义 |
|---|---|
| **2** | **压力源相同，且情绪状态相同**。用户读到会觉得「这说的就是我」 |
| **1** | 只满足一个：同一压力源但情绪不同（query 是麻木，帖子是愤怒）；或情绪相同但压力源是相邻的另一件事（同样是周日夜里心慌，一个因为上班、一个因为论文） |
| **0** | 压力源和情绪都不同；或帖子在给建议、讲道理、灌鸡汤而不是表达处境；或只是同一个场景词（都提到「地铁」）但感受无关 |

判别要点：
- **处境维度只用来在 1 和 2 之间犹豫时做决定**：压力源与情绪都对上了但人生阶段明显不同（query 是学生、帖子是 40 岁中层），仍给 2；只有一项对上时，处境相近可以帮它保住 1。
- 帖子语气比 query 轻（query「撑不下去」，帖子「今天有点累」）：压力源相同时给 **1**，情绪强度差太远不算「同一种感受」。
- 抒情、鸡汤、格言体（「成年人的世界没有容易二字」）：没有具体处境，给 **0**，除非它明确在描述自己正在经历同一件事。
- 帖子表达了 query 没提到的更强烈情绪（例如自伤倾向）：只按上面的维度判定相关性，不因内容沉重加分或减分。

## 常见陷阱

1. **关键词陷阱**：query「通勤两小时」，帖子「两小时的电影看睡着了」→ 0。
2. **话题对了但人不对**：query 求同类，帖子是第三人称科普「职场倦怠的五个信号」→ 0（它在讲道理，不在表达处境）。
3. **话题对了但需求不对**：query 求答案「押一付三怎么周转」，帖子只抱怨「押一付三压力好大」→ 1（同一问题，没有信息）。
4. **犹豫时不往高打**：在 1 和 2 之间拿不准，给 1；在 0 和 1 之间拿不准，看用户读到会不会觉得「有点用 / 有点像」，会就给 1。

## 输出

每条候选给出 `grade`（0 / 1 / 2）和一句不超过 30 字的理由。理由写判断依据（「同一压力源，情绪不同」），不要复述帖子。
